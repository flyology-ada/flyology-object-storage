# Discovery areas

Fifteen areas, launched in batches of four. Each agent reads
`review/DISCOVERY_PROMPT.md` first and writes `review/discovery-<AREA>.md`.

| Batch | AREA | Scope (paths relative to the worktree root) |
|---|---|---|
| 1 | WIRE | `src/flyology-object_storage-s3-wire_core.ad?`, `-s3-xml.ad?`, `-s3-xml_writers.ad?`, `-s3-strict_xml_codecs.ad?`, `-s3-requests.ad?`, `-s3-core.ad?`, `-s3-imf_dates.ad?`, `src/flyology-object_storage.ad?` (root validation domain), `src/flyology-object_storage-s3.ads`. The SPARK boundary (`docs/architecture/spark-coverage.md`, `proof-status.md`). Bounds, XML entity safety and SAX orchestration, byte-range parser, decimal and size scalars, request-target classification, IMF-fixdate parsing and rendering, bucket and key validation. |
| 1 | SIGV4 | `src/flyology-object_storage-s3-sigv4.ad?`, `-s3-sigv4_encoding.ad?`, `-s3-sigv4_verification.ad?`, `src/flyology-object_storage-server-authentication.ad?`, `-server-static_credentials.ad?`, `-server-mfa.ad?`, `src/flyology-object_storage-secrets.ad?`. Canonicalisation against the AWS SigV4 test-suite rules, timestamp windows, presigned URLs, chunked and trailer signing, constant-time comparison, credential scope, header ordering, duplicate headers, URI encoding of keys and query values, session tokens, secret erasure. |
| 1 | BACKEND-FILES | `src/flyology-object_storage-backends-files.ad?`, `src/flyology-object_storage-durability.ad?`, `src/flyology_object_storage_durability.c`, `src/flyology_object_storage_secure_erase.c`, `docs/architecture/files-layout.md`, `tests/src/files_*probe.adb`, `tests/src/flyology-object_storage-backends-files-testing.ad?`, `tests/src/flyology-object_storage-durability_testing.ad?`. Atomic publication, key path encoding, symlink and traversal safety, fsync ordering and crash consistency, partial writes, rename semantics, supplied ETag handling, multipart and versioning state on disk, reopen and reconciliation. |
| 1 | SERVER | `src/flyology-object_storage-server-s3_applications.ad?`, `src/flyology-object_storage-server.ads`, `-server-metadata_results.ads`, `-server-object_lambda_responses.ads`, with `tests/src/s3_server_harness.ad?` and `tests/src/s3_server_application_corpus.adb` as the callers. Request classification and routing, error XML and status codes, authorisation policy, conditional and range responses, chunked uploads and payload-hash verification, multipart on the server side, versioning routing, ACL profile, request deadlines and body bounds. |
| 2 | BACKEND-MEMORY | `src/flyology-object_storage-backends-memory.ad?`, `src/flyology-object_storage-backends.ad?`, `-backends-listing.ad?`, `-backends-bucket_listing.ad?`, `-backends-multipart_listing.ad?`, `docs/architecture/memory-backend.md`, `tests/src/flyology-object_storage-backends-testing.ad?` and the conformance programs. Capacity reservations under concurrency, listing semantics (delimiter, prefix, start-after, continuation tokens, key and version markers, common prefixes), conditional writes, versioning states, multipart lifecycle, delete markers, the backend interface contracts themselves. |
| 2 | CHECKSUM | `src/flyology-object_storage-s3-checksums.ad?`, `-s3-checksum_crc.ad?`, `-s3-checksum_policy.ad?`, `src/flyology-object_storage-checksum_engine.ad?`, `src/flyology_object_storage_xxhash.c`, `vendor/xxhash/`, `docs/architecture/s3-checksums.md`, `tests/src/s3_checksum_corpus.adb`, `tools/generate_s3_checksum_corpus.py`. All ten algorithms, composite and full-object modes, canonical base64, trailers, CRC combination arithmetic, streaming engine state, C shim ABI. |
| 2 | TRANSFERS | `src/flyology-object_storage-client-transfers.ad?`, `src/flyology-object_storage-s3-multipart.ad?`, `docs/architecture/client-transfers.md`, `tests/src/flyology-object_storage-client-transfers-testing.ad?`, `tests/src/s3_transfer_many_corpus.adb`. Part sizing, the 10,000-part and 50 TiB bounds, range arithmetic, resume, part checksums, concurrency and cancellation, structured-task ownership (no detached task outlives the call), result aggregation. |
| 2 | BACKEND-SQLITE | `sqlite/src/*` (not the vendored amalgamation), `docs/architecture/sqlite-backend.md`, `sqlite/tests/src/*`. Catalogs, migrations, transaction boundaries, the versioning merge `CASE` update, reopen behaviour, payload files outside the database, lock ownership, error mapping from SQLite result codes, statement finalisation and resource leaks. |
| 3 | CLIENT-LOW | `src/flyology-object_storage-client-low_level.ad?`, `-client-bounded_rest_xml_reads.ad?`, `-client-paginated_rest_xml_reads.ad?`, `-client-rest_xml_mutations.ad?`, `src/flyology-object_storage-s3-paginated_rest_xml_reads.ad?`, `src/flyology-object_storage-client.ads`, `docs/architecture/composable-client-operations.md`. The spec is 10,600 lines and the body 17,400; sample by operation family rather than reading linearly. Request building, response and error parsing, retry and redirect behaviour, header canonicalisation, state machines of the composable operations, body ownership and streaming. |
| 3 | CLIENT-OBJECTS | `src/flyology-object_storage-client-objects.ad?`, `docs/architecture/client-objects.md`, `docs/qualification/{get-object,head-object,put-object,delete-object,copy-object,object-tagging,get-object-attributes}.md`, `tests/src/flyology-object_storage-client-objects-testing.ad?`. Typed outputs, error outcomes, non-replay guarantees, conditional headers, range handling, metadata round trips. |
| 3 | MODEL | `tools/generate-s3-model.py`, `tools/s3_codegen.py`, `tools/s3_operation.py`, `tools/s3-operation.py`, `tools/test-s3-operation-registry.py`, `src/flyology-object_storage-s3-model.ads`, sampled regions of `src/flyology-object_storage-s3-model.adb`, `coverage/`, `tools/verify-*-preparation.py` (sample), `review/baseline/service-2.json` (the pinned model). Logic that would be wrong in every generated descriptor: enum mapping, member locations, XML traits, required-member handling, HTTP bindings, error shapes, host-prefix and payload traits, checksum and auth traits. Compare sampled descriptors against the JSON. |
| 3 | SERVER-EXE | `server/src/*`, `server/README.md`, `server/tests/scripts/test.sh`, `server/assets/`. Configuration parsing, bootstrap credential creation and slow hashing (`..._credentials_native.c`), management sessions and cookies, signals and drain, listener binding, asset pinning, backend selection. Security surfaces first. |
| 4 | CLIENT-BUCKETS | `src/flyology-object_storage-client-buckets.ad?` (18,900-line spec, 28,600-line body), `docs/architecture/client-buckets.md`, `tests/src/flyology-object_storage-client-buckets-testing.ad?`. Sample by family: paginated listings (cursors, markers, continuation tokens, truncation), bounded reads, mutations with non-replay guarantees, error outcomes, typed outputs. Look for logic shared across families that would be wrong everywhere. |
| 4 | S3-DOMAIN-A | Bucket-level typed codecs: `src/flyology-object_storage-s3-{acl,lifecycle,replication,notifications,versioning,versions,listings,buckets,bucket_controls,encryption,website,logging,inventory,analytics,metrics,intelligent_tiering,metadata_configurations,metadata_tables}.ad?` and `src/flyology-object_storage-s3-generated_*_xml.ad?`, against the pinned model and `docs/qualification/`. Decoder and encoder fidelity, required members, enum coverage, bounds, duplicate elements, ordering, empty-element handling. |
| 4 | S3-DOMAIN-B | Object-level typed codecs and shared vocabulary: `src/flyology-object_storage-s3-{object_lock,annotations,attributes,tagging,deletions,copies,errors,object_reads,multipart_uploads}.ad?`, `src/flyology-object_storage-tags.ad?`, against the pinned model and `docs/qualification/`. Same checks as S3-DOMAIN-A, plus error-code mapping and the DeleteObjects quiet mode. |
